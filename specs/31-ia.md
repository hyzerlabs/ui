> Theme hooks (R9–R10) add: `src/docs/hooks.ts` + `src/docs/hooks.spec.ts`

### Goal

Fix the top-level taxonomy bug — "Components" currently sits beside Layout,
Media, Forms, and Navigation, which are all components — by consolidating
every component page under one **Components** section with presentational
groups, flattening all 38 component URLs to `/components/<name>`, and adding
a **Pages** section for full-page sample compositions that render inside the
docs frame through a breakout container.

The same pass closes a second gap: components document their *props* but not
their *styling contract*. The reference theme styles `hz-*` root classes and
`data-*` hooks, and `/theming/components` teaches that those hooks exist —
but a reader on `/components/button` can't find out what Button's actually
are without reading the theme CSS. Every component page grows a **Theme
hooks** table (R9), sourced from one curated module that also generates the
theming page's roll-up (R10).

Decisions locked with the user (2026-07-16): sidebar groups are
**non-collapsible labeled headers** (no second disclosure level); the
catch-all group is named **Common** (renamed from General, 2026-07-17; group
order is Common, Layout, Navigation, Media, Forms); URLs **flatten for all 38**;
the section is named **Pages**; samples render **inside the doc-site frame**
— sidebar stays for navigation, content bleeds via a giant breakout; theme
hooks are a **separate table in the props-table format**, **curated in
`src/docs/hooks.ts`** rather than derived, covering **all 38 pages**, with
the `/theming/components` table **generated from that module**.

### Target information architecture

```
Introduction        /
Getting Started     /getting-started
Foundation          (unchanged: colors, typography, contrast, spacing,
                     radius-elevation, motion, icons, reset)
Components          /components/<name>  — one section, grouped:
  Common            alert, badge, blockquote, button, link, card, divider,
                    dropdown, carousel, hero, modal, accordion, tabs
  Layout            container, stack, cluster, grid, split, virtualizer
  Navigation        nav, breadcrumbs, pagination, footer
  Media             image, lightbox, video
  Forms             form, text-input, textarea, select, combobox,
                    file-upload, checkbox, radio-group, slider,
                    range-slider, color-input, toggle
Theming             (unchanged: overview, tokens, components, examples)
Pages               /pages/<name> — full-page sample compositions
```

Top-level reads as the adoption arc: learn → raw materials → parts → make it
yours → put it together.

### Requirements

1. **R1 — Manifest gains a group tier.** `ManifestSection` supports grouped
   children: a section carries either flat `children: ManifestPage[]`
   (Foundation, Theming, Pages) or `groups: { label: string; pages:
   ManifestPage[] }[]` (Components). `allRoutes` and every manifest consumer
   handle both shapes. Group labels are presentational only — no routes, no
   hrefs, no disclosure state.
2. **R2 — Nav heading entries.** `NavItem` gains a heading subtype (e.g.
   `{ heading: string }`) valid inside a `children` array: rendered as a
   static, non-focusable, non-interactive group label `<li>` between link
   items. It has no href, emits no button, and is skipped by keyboard
   traversal (it is plain text in the list; screen readers read it in
   sequence). Supported in vertical orientation; horizontal dropdown panels
   render it identically. Amend `specs/04-nav.md` with the subtype and its
   non-interactive contract. The docs shell maps Components groups onto
   heading entries.
3. **R3 — Flat component URLs.** All 38 component pages live at
   `/components/<kebab-name>`: the 25 pages under `src/routes/{layout,
   navigation,forms,media}/` move (`git mv`) into `src/routes/components/`;
   the existing 13 stay put. No name collisions exist. Old URLs 404 — no
   redirects (greenfield; the site's only consumer is itself).
4. **R4 — Internal link sweep.** Every in-site link to a moved URL
   (`/forms/*`, `/layout/*`, `/media/*`, `/navigation/*` in pages, docs
   components, and code samples) updates to the flat path. The prerender
   crawl is the enforcement — it fails on any missed internal link.
5. **R5 — Pages section + first sample.** New manifest section **Pages**
   with one inaugural sample: **Homepage** (`/pages/homepage`) — a
   marketing-style landing composed from the library (Hero, Card grid,
   Badge/Button usage, Footer; disc-golf-true content). Convention it
   establishes:
   - The composition lives as a self-contained docs component
     (`src/docs/samples/Homepage.svelte`) importing only public `$lib`
     exports — it must read like consumer code.
   - The route (`src/routes/pages/homepage/+page.svelte`) renders a short
     intro (what the sample demonstrates, which components it composes,
     linked), then the composition inside `<Container breakout
     padding="none">` so it bleeds across the full main column while the
     sidebar stays for navigation, then the full source in a CodeBlock
     (`?raw` import of the sample component).
   - Sample-internal navigation (its Nav/Footer links) uses bare `#` hrefs
     (prerender crawler exemption; readers don't navigate away).
6. **R6 — Sidebar behavior.** The Components toggle opens to the grouped
   list (five headers, 38 links); active-page detection, `aria-current`,
   and auto-expand of the active section keep working across the new
   structure. Foundation/Theming/Pages sections unchanged in behavior.
7. **R7 — No dead chrome.** The old section index behavior is already
   label-only (no cover pages) — verify nothing still links `/forms`,
   `/layout`, `/media`, `/navigation` as URLs (landing cards, breadcrumbs
   demos, e2e).
8. **R8 — Spec bookkeeping.** `specs/16-docs.md`: IA table and R4 replaced
   by a dated amendment reflecting this spec (flat component URLs, grouped
   section, Pages). `specs/04-nav.md`: heading-entry amendment (R2).
   Historical specs referencing old URLs are not rewritten.
9. **R9 — Theme hooks on every component page.** Each of the 38 component
   pages surfaces its styling contract — the hooks a consumer writes CSS
   against — in a **Theme hooks** section rendered as a table in the same
   format as the props table, placed after Props and before Accessibility.
   - **Single source: `src/docs/hooks.ts`.** One `ComponentHooks` entry per
     component, keyed by component name: `{ root: string; attrs: HookRow[];
     props: HookRow[] }` where `root` is the stable root class
     (`hz-button`), `attrs` are the `data-*` hooks, and `props` are the
     `--hz-*` custom properties. Rows carry `{ name, values, note }`.
     The page slice and the `/theming/components` roll-up both read this
     module — the table on that page is generated from it (R10), so a hook
     is described in exactly one place.
   - **Curated, not derived.** The hook list is authored, because neither
     source can produce it honestly. Components stamp attributes that are
     not a promise to consumers — `data-index` (Virtualizer) is a JS↔DOM
     correlation key no CSS selects, and `--hz-grid-cols*` / `--hz-grid-min`
     are written inline by Grid from its `columns` prop, so overriding them
     fights the prop rather than complementing it. And the reference theme
     is not the whole surface: Container, Stack, Cluster, Grid, Split and
     the form controls have no sheet of their own, while
     `--hz-breakout-shift` and `--hz-footer-col-min` are never declared
     anywhere — they exist only as `var(--hz-x, fallback)` reads, and the
     docs shell relies on the first. Curation decides what is contract; the
     tests below decide whether the curation is true.
   - **The bar for "not contract" is high.** An attribute stamped 1:1 from
     a public prop is contract even if it looks incidental — `data-fraction`
     (Split) and `data-placeholder` (Image) both are, and both are styled.
     Plumbing means the consumer cannot meaningfully set it or the value is
     derived state the component owns. When in doubt, document it.
   - **Scope of a hook.** A row belongs in the table when a consumer can
     rely on it: the root class, any `data-*` the component stamps as part
     of its variant/state vocabulary, and any custom property read via
     `var()` with the intent that it be overridden. Internal derivations
     stay out and are listed in the test's allowlist with a reason.
10. **R10 — `/theming/components` roll-up.** The hand-written
    custom-property table on that page is replaced by a table generated
    from `hooks.ts` (every component's `props` rows, component column
    derived from the key). The page's prose, code samples, Card-treatment
    and headless sections stay as they are — only the table's data source
    changes. The page keeps teaching the concept; the pages own the detail.

### Accessibility

- Heading entries are static text in the list — no role="separator", no
  focus stop, no aria-hidden (the label is information). Reviewer verifies
  a screen reader reads "Layout" before its links and that Tab skips it.
- The Homepage sample is held to the library's own bar: landmarks
  (`header`/`main`-equivalent structure within the demo, one h1 INSIDE the
  sample is not allowed — the route's h1 is the page title; the sample's
  top heading is h2-level via headingLevel props), alt text on sample
  media, and the intent-color-is-reinforcement rule.
- Breakout content must not introduce horizontal overflow at 375px (the
  existing responsive e2e covers every route from the manifest).

### Edge Cases & Error States

| Case | Expected behavior |
| --- | --- |
| Bookmarked old URL (`/forms/select`) | 404 — accepted, greenfield; no redirect layer in adapter-static. |
| Manifest group with zero pages | Disallowed — parity/unit test fails the build. |
| Heading entry passed to a horizontal top-level items list (not inside children) | Out of contract — Nav renders nothing for it and dev-mode may warn; spec 04 documents children-only support. |
| Sample page at 375px | Breakout collapses gracefully; no horizontal overflow (e2e). |
| Sample Nav inside the docs shell | Nested `<nav>` landmarks carry distinct `ariaLabel`s (docs sidebar vs. sample nav). |
| Prerender crawl after the move | All 38 flat routes + `/pages/homepage` render; any stale internal link fails the build. |
| Component page with no hooks entry | Disallowed — coverage test fails. Every component page has a root class at minimum. |
| Documented hook that no longer exists in source | Test fails — the name must appear in the component's source or the reference theme CSS. |
| New `--hz-*` hook added to the theme, undocumented | Test fails — the theme's declared hooks must be documented or explicitly allowlisted as internal. |
| Hook read but never declared (`--hz-breakout-shift`) | Valid and documentable — the test matches the name in `var()` position too, not just declarations. |
| Component with hooks the reference theme doesn't style (Stack, Grid) | Valid — the contract is the component's, not the theme's. Test looks in component source. |
| Internal plumbing attr (`data-index`) | Out of contract — undocumented by design; allowlisted in the test with a reason. |

### Existing Code to Reuse

- `Container breakout` + the docs shell's `--hz-breakout-shift: 0` on
  `.docs-main` — the sample bleed needs zero new layout machinery.
- Manifest-driven docs e2e (route lists derive from `allRoutes`) — new
  routes join the overflow/crawl suites automatically.
- `?raw` source display convention (reset page, theming examples).
- Nav vertical disclosure sections (specs/04) — heading entries slot into
  the existing children rendering, not a new mode.
- `PropsTable.svelte`'s table styling — the Theme hooks table matches the
  props table's format, so `ThemeHooks.svelte` reuses that presentation
  rather than growing a second table look.
- `fallback-parity.spec.ts` — the pattern for a test that reads shipped CSS
  off disk and holds a docs claim to it; `hooks.spec.ts` is the same shape.
- The `class` row already on every props table names the root class — R9's
  `root` supersedes it as the canonical statement; the props row stays
  (it's a real prop) but stops carrying the contract alone.

### Test Plan

**Unit (server):** manifest shape — Components section has the five groups
in order with 38 unique flat hrefs; every group non-empty; `allRoutes`
includes all pages exactly once. Nav heading-entry rendering (browser
component test): heading renders as non-focusable text, links around it
keep roving/disclosure behavior.

**Unit — `hooks.spec.ts` (R9's enforcement).** The curation is only worth
shipping if it can't rot. Four checks, reading real source off disk the way
`fallback-parity.spec.ts` does:

1. *Coverage* — every component in the manifest's Components section has a
   `hooks.ts` entry with a non-empty `root`.
2. *Root class is real* — each `root` appears literally in that component's
   `.svelte` source.
3. *No fiction* — every documented `data-*` appears in the component's own
   source; every documented `--hz-*` appears in the component's source or
   in `src/lib/theme/**` (excluding `examples/`), in either declaration or
   `var()` position.
4. *No drift* — every `--hz-<name>-*` declared in the reference theme is
   documented in `hooks.ts` or listed in `INTERNAL_HOOKS` with a comment
   saying why it's internal (e.g. `--hz-field-ring`, a derivation the
   field controls share).

Checks 3 and 4 are the two directions that matter: 3 stops the docs
promising hooks that don't exist, 4 stops new hooks shipping undocumented.
Neither is satisfiable by a lint rule — they compare prose to source.
Substring matching is the deliberate floor: it catches deletion and rename,
not semantic change, and buying more than that means a CSS parser the value
doesn't justify.

**e2e:** a component page renders its Theme hooks table (Button: root class
`hz-button`, `data-variant` row, `--hz-button-accent` row);
`/theming/components` roll-up lists every documented custom property.

**e2e:** sidebar Components toggle shows group headers and navigates to a
moved page (e.g. Select at `/components/select`); active link aria-current
on a moved page; `/pages/homepage` renders the sample full-bleed (assert
the sample's width exceeds the prose column) with no horizontal overflow at
375px; existing suites re-green over the manifest.

**Build:** prerender crawl green (R4's enforcement); `pnpm package` +
publint unaffected (docs-only + Nav change).

### Out of Scope

- Additional sample pages (product listing, blog index — follow-ups once
  the Homepage proves the frame).
- Redirects from old URLs.
- The sidebar search bar (separate roadmap item; groups make it more
  valuable, not less).
- (Resolved 2026-07-17) The "General" group was renamed **Common** and the
  groups reordered to Common, Layout, Navigation, Media, Forms.
- Nav API beyond the heading entry (no nested disclosure levels).
- Hooks on non-component pages (Foundation, Theming, Pages) — R9 is the
  component contract; those pages have no component to contract about.
- Adding, renaming, or filling gaps in the hook surface itself. R9 is
  documentation of what exists. A missing hook found while authoring is
  reported, not invented — inventing one here would ship an API change
  disguised as a docs change.
- A CSS parser for the pinning test (substring matching is the agreed
  floor — see Test Plan).
